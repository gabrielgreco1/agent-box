# AB-032 · Skills nativas no lançamento Claude

O Claude Code 2.1.301 instalado aceita `--plugin-dir <path>` para carregar um plugin somente na sessão. A documentação oficial descreve `skills/<name>/SKILL.md` como layout padrão do plugin e diz que o manifesto é opcional; o nome do plugin vem do diretório. Referências: [CLI](https://code.claude.com/docs/en/cli-reference), [plugins](https://code.claude.com/docs/en/plugins), [manifesto/layout](https://code.claude.com/docs/en/plugins-reference), [skills](https://code.claude.com/docs/en/skills).

Para cada execução Claude com skills selecionadas, `prepare` confirma que o SHA-256 do texto importado ainda corresponde ao catálogo, rejeita nomes de comando inválidos ou duplicados e planeja cópias exatas em `LaunchContexts/<run>/agentbox-<run>/skills/<skill-id>/SKILL.md`. O plano e o review mostram argv, caminho, texto e proveniência. `materialize` grava o plugin protegido ao lado de `context.md` somente após confirmação do digest revisado. O argv usa `--append-system-prompt-file <context.md> --plugin-dir <plugin>`; o prompt e a TUI nativos são preservados. O texto da skill também segue no contexto revisado, de modo que o digest atual da UI ainda cobre o conteúdo autorizado. A skill passa a estar disponível como comando nativo namespaced `/agentbox-<run>:<name>` (ou ID se não houver `name` no frontmatter).

O binding persistido inclui ID, origem e hash de cada skill. No restart explícito, o planner reconstrói caminhos/argv e verifica os arquivos antes de devolver um terminal. O runtime verifica novamente o snapshot antes de iniciar. A limpeza remove contexto e plugin da execução. Nada escreve em `~/.claude`, `.claude/` do projeto ou configurações globais.

Limite: a biblioteca importa apenas o arquivo de texto da skill. Arquivos auxiliares, scripts e referências relativas do pacote de origem não são capturados; uma skill que depende deles pode aparecer no menu mas não executar por completo. O código não inicia uma sessão Claude como teste de integração, portanto a prova atual é o contrato CLI/documentação + testes de layout, hash, argv, restauração e adulteração. Codex/OpenCode permanecem export-only até haver adapters verificados.
