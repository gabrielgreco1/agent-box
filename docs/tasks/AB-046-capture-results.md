# AB-046: capture and results foundation

Capture is disabled by default. The Core wire contract accepts schema version 1 with `capture_id`, `coverage_version`, `computer_id`, coverage, gaps, events, cursor, and dropped count. The host supplies immutable session, terminal, optional native child run, and computer IDs after verifying the caller. Ingest requires an enabled configuration with exact hosts and path prefixes. It revalidates every event, removes URL query/fragment and unselected JSON fields, and stores no headers or raw bodies. Field names associated with credentials are disallowed; the selected scalar values remain user-visible capture data and should be chosen narrowly. Coverage gaps and drop counts remain inspectable.

`CaptureStore` persists bounded private archives per computer. It rejects symbolic links, unsafe ownership/permissions, oversized files, and corrupt or altered evidence rather than treating them as empty data. Polling the same capture ID and event again is idempotent: the append result reports a replay, while the persisted record stays one observation. An event from a later runtime capture ID remains separate even when sequence numbers restart. Expiry is enforced on reads as well as appends. Event-count or file-size pressure removes the oldest evidence first and increments the local-drop count; runtime-reported drops are tracked per capture ID. Deleting captures does not delete saved results.

`DatasetStore.create` makes rows only from selected capture records belonging to one computer and selected JSON field names. Each row keeps source URL, timestamp, host identity, capture ID, record ID, evidence hash, and duplicate count. `list(computerID:)` returns only results for that computer after relaunch. A field unavailable in the sanitized selection becomes JSON null with `field_unavailable` (missing, unselected or unsupported scalar), or `body_not_captured` when no body was retained; a source null has `source_null`. CSV and JSON exports go into a fresh private directory with a separate manifest containing export time, data SHA-256, and evidence hashes. Existing export files are never replaced. CSV string cells that could be interpreted as formulas are prefixed with an apostrophe.

## Runtime and app integration

The computer panel opens **Capturas e dados** for running or stopped boxes. Stored history and datasets remain readable offline; configuring or clearing the runtime requires the same verified, running computer. Preferences are private per-computer files. Opening the panel never enables capture. An enabled capture is polled in the background while this app process is alive, even when its panel closes; transient connection failures retry with backoff. A confirmed stopped/disabled runtime stops the collector. Relaunch restoration still requires reopening its panel. Apply validates exact hosts, selected scalar JSON fields and retention before sending the authenticated configuration. Browser generation changes do not invalidate the capture cursor: a separate capture UUID rotates on configuration change, explicit clear and process restart.

The runtime observes Playwright context requests/responses/failures in headless and desktop, including new pages; its sync event loop is pumped while no browser command is queued. Only completed/failing requests become records. URL userinfo, query and fragment are excluded; paths retain only explicitly approved static prefixes. These prefixes control retained text, not a request-path filter. No browser response bodies, headers, request bodies, form values or cookies are stored. The controlled HTTP GET/HEAD tool may retain explicitly selected top-level scalar JSON fields within the configured response limit. A field allowlist is not a classifier for personal data: users must select fields appropriately.

The runtime ring is bounded to 900,000 serialized event bytes, at most 1,000 records and a maximum 24-hour retention, with drop counts. It has no capture disk file. The host validates again, adds the verified owner identity, and persists in bounded private archives. A terminal-owned computer has no asserted initiating run; a child-owned computer records its owner run. Background browser traffic must not be falsely attributed to the model's current tool call.

The agent cannot enable capture through MCP: configuration is a user UI action. Captured-data MCP access is not implemented in this checkpoint. Existing HTTP tools still return their direct response to their verified caller.

## Remaining gates

- The implementation declares gaps for worker-internal requests, WebSocket frames, cache details, browser bodies, curl, Python requests/curl_cffi, raw sockets and proxy traffic. It does not claim universal network interception or AC51/AC52 completion.
- Changing filters rotates and clears the runtime ring. Draining before Apply reduces loss, but requests finishing between the drain and configuration change can be lost. Atomic cutover is pending.
- Runtime collection continues in its bounded ring without the app. Automatic host collector restoration after app relaunch, durable cursor recovery and extended load/backpressure acceptance remain pending.
- Global/project/agent listener policy inheritance, method/status/MIME filters and interception/rewriting are not delivered by this per-box opt-in.
- JSON datasets currently select scalar top-level fields from controlled HTTP captures. Browser JSON bodies, nested field extraction, business-key deduplication and dataset editing are future work. Replayed transport events are idempotent; distinct network requests are not merged merely because their payloads look alike.
- The native panel's interactive/visual acceptance remains pending while the Mac is locked. Existing user boxes need an explicit stopped-box image update before the new runtime APIs are available.
