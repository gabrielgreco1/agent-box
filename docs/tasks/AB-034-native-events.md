# AB-034 · Transporte opt-in de eventos nativos Claude Code

`ClaudeHookInboxConfiguration.create` prepara um `--settings` adicional e um inbox privado por lançamento. O caller escolhe um UUID de run **antes** de lançar Claude, passa `environment` ao processo e adiciona `--settings <settingsURL>` aos argumentos. Depois que o PTY informa `.running(pid:)`, grava `recordTerminalStart(..., runID:)` com o mesmo UUID. Então pode chamar `ClaudeHookInbox.drain()` periodicamente e ao término. O app ainda precisa fazer essa integração; este lote não instala hooks nem ativa captura por padrão.

O comando em `runtime/hooks/claude_event.py` lê o JSON recebido no stdin do Claude Code e escreve somente `run_id`, `session_id`, `hook_event_name`, `agent_id` e `agent_type`. Não armazena prompt, saída do agente, transcript ou cwd. O evento carrega HMAC SHA-256 ligado ao segredo efêmero de 256 bits do lançamento. O inbox tem permissão `0600`, limite de 1 MiB e linhas de até 4 KiB; o hook descarta entradas que excedem os limites e sempre sai sem bloquear Claude. O consumer confirma assinatura, run, payload e correlação de sessão antes de gravar a identidade. `SubagentStop` sem início observado é ignorado. Texto do PTY nunca entra no registro.

O segredo no ambiente e o inbox privado defendem contra eventos acidentais ou outro processo sem o segredo; não são isolamento contra código malicioso que roda sob a mesma conta e herda o ambiente do próprio Claude. O inbox é metadado de observação, não autorização para controlar o filho. O transporte atual não fornece PID ou TTY individual de subagentes. A API marca `liveSubagentCapture=false` até o app integrar e validar o caminho com uma execução real autorizada. Um consumer recriado pode reler eventos enquanto o run pai ainda está ativo. Ainda falta checkpoint/reconciliação robusta quando o processo pai morre ou o inbox excede o limite.

Fonte verificada: [Hooks reference](https://code.claude.com/docs/en/hooks), seções `SessionStart`, `SubagentStart`, `SubagentStop`, entrada comum via stdin e configuração `--settings`. As seções de subagente documentam `session_id`, `agent_id` e `agent_type`; `SubagentStop` pode ocorrer para agentes internos, então é exigido início prévio. Teste local usa o mesmo hook com fixtures JSON, sem executar tarefa paga.
