# AB-036 — Scraping agent default

The Library has a **Web scraping** action that creates or opens a saved Claude agent with the user's installed `~/.claude/skills/webscraping-expert/SKILL.md` selected by default. It imports the local source at the moment the user creates the preset. Other agents and plain terminals are unchanged. If the source is absent, creation fails with a visible error; no empty skill is created. The user's global skill directory is never modified, and its contents are never checked into this repository.

For a reviewed Claude launch, Agent Box checks that the original `SKILL.md` still matches the imported hash. It reads the supporting package beneath that file, freezes every eligible file into the launch plan, and shows paths and SHA-256 values during review. Materialization writes protected local plugin files. Relaunch checks their hashes against the saved binding. The package reader caps individual files at 1 MiB and the package at 200 support files and 5 MiB. It rejects links, special files, invalid paths, and likely credential filenames; hidden files such as `.DS_Store` are excluded.

When the browser box is created, Agent Box ensures the local Web scraping agent exists and durably records its agent ID and skill ID alongside the new computer ID and the terminal ID that owns the box. The panel shows **skill pending** and offers **Revisar e iniciar agente**, which opens the existing saved-agent launch review. This is a default assignment at box creation, not an activation claim. If the local `SKILL.md` is absent, box creation fails visibly before Docker creation. Supporting files are checked when the reviewed launch is prepared. If an older box lacks an assignment, or saving the assignment failed after Docker creation, the panel offers **Definir agente de scraping padrão** to repair it.

The skill package is supplied only to a newly reviewed Claude launch, never injected into an already running CLI. AB-038 now reuses the stopped terminal that owns the box: the review fixes its session and directory, requires the assigned skill, revalidates Docker ownership, and creates a fresh plan on the same terminal ID. The panel reports inclusion only when the active process matches that plan. See [AB-038](AB-038-same-terminal-agent-launch.md). AB-039 now supplies browser tools through local MCP for the assigned Claude launch. Actual model invocation of the skill and tools still needs live verification.

The package filter also rejects a few high-confidence secret signatures in text (private key blocks, AWS access key IDs, and GitHub tokens). This is a safety check, not a general credential detector.

Verification: integrated Swift suite passed 82 tests, including freezing, tampering, missing source, links, private-key text and assignment persistence. Release app build and ad hoc signature passed. Interactive CLI activation and the complete box/agent attachment flow remain unverified. Browser Docker validation is recorded separately in AB-037.

## Navegador comum e CAPTCHA

Desktop usa Chromium visível como processo independente, perfil persistente por box e sem override de user agent. Headless já executa JavaScript. O perfil não é o perfil pessoal do Chrome no Mac, e não é copiado dele. Novas boxes recebem a atribuição do preset local; o lançamento revisado inclui o pacote completo elegível da skill. Uma atribuição não significa que um processo já em execução carregou a skill.

A skill orienta extração; não garante ausência de CAPTCHA. O [suporte do Google](https://support.google.com/websearch/answer/86640?hl=pt-BR) descreve bloqueios associados ao tráfego da rede. Não há evidência suficiente para atribuir o bloqueio observado ao user agent. Diagnóstico deve comparar modo, perfil, caminho de rede e cadência sem registrar cookies ou tokens. Diante de verificação humana, interromper as tentativas e pedir takeover no mesmo computador. O comportamento real do Google ainda não foi revalidado.
