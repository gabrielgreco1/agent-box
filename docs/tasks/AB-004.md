# AB-004 · Fundação Docker e política de computadores

## Entregue neste lote

- Política JSON versionada e persistente em `Application Support/AgentBox/computer-policy.json`. O padrão é criação desativada; só a opção manual permite criar/iniciar no painel de um terminal. A preferência Adaptativo/Sempre gráfico é persistida, mas o painel esclarece que os dois modos gráficos aguardam implementação.
- Detecção do executável Docker e probe limitado do daemon (`docker version`). As configurações mostram ausência do CLI, falha do daemon ou versão observada, sem iniciar ou instalar runtime.
- Serviço de containers vinculado a UUID de terminal com `createAndStart`, `stop`, `computer(for:)` e `listManagedComputers`. O usuário dispara criação/início/parada explicitamente. O serviço confere labels de propriedade e terminal antes de iniciar/parar um container existente; um conflito de nome não é sobrescrito. Containers são preservados ao parar; nenhuma rotina os remove automaticamente.
- Criação com imagem `python:3.12.8-slim-bookworm`, Python padrão disponível para futuros workers HTTP. Há limite de 1 CPU, 768 MiB e 128 PIDs, filesystem raiz read-only, tmpfs `/tmp` limitado, usuário sem privilégios, `cap-drop=ALL` e `no-new-privileges`. Não há Docker socket, mounts do host, portas publicadas ou `--privileged`. O `docker create` pode baixar a imagem somente após o clique explícito; a tag fixa versão, mas não equivale a digest imutável.
- Runner usa `Process` com argv, stdin nulo, timeout e limite de captura de saída. Não interpola shell.

## Limites reais

Esta box inicial é um container Linux HTTP-capable, **sem endpoint de ferramenta para agentes**. A vinculação segura a subagente nativo aguarda o gate M5; não há browser, perfil, desktop, vídeo ou streaming. A preferência gráfica não muda o modo efetivo. O container é ligado ao terminal selecionado, e nenhuma atribuição a filho é inferida. Não existe ainda workspace/perfil persistente montado: parar preserva o container, mas `/tmp` é transitório e o filesystem raiz é read-only. O volume, perfil, política de rede local e controle de acesso por agente precisam ser implementados antes de disponibilizar uma ferramenta de navegação/HTTP aos CLIs. O Docker daemon, quando presente, continua uma autoridade ampla do usuário; esta interface apenas restringe os comandos que ela própria emite.

- Runner real: há um teste adicional de argv literal e timeout; requer recompilar testes após cessarem as edições paralelas dos demais módulos.
- `swift build --target AgentBoxCore` passou com o Xcode ativo.
- `swift test --filter DockerComputerTests` compilou os arquivos Docker; o build completo ainda ficou interrompido por `RuntimeLifecycle`/views do integrador em trabalho paralelo. Uma tentativa posterior com scratch isolado detectou `WorkspaceStoreTests.swift` alterado durante o build. Reexecutar no gate de integração.
- `command -v docker` não encontrou Docker nesta máquina. Nenhum daemon foi iniciado, nenhuma imagem baixada e nenhum container criado.

Integração final: 23 testes sem falha; PTY revalidado após ajuste de grupos (2 testes). Docker real não disponível. Veja docs/STATUS.md.
